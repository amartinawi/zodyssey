# The delegate-skills + review-skills adaptation study

Two external skill collections were studied for what ZOdyssey could adopt: **delegate-skills** (a fleet of relay scripts that delegate briefs to other AI coding CLIs and review the diff they produce) and **review-skills** (two-model PR review plus a PR-sitting loop that verifies bot findings before believing them). The question was the ISNAD question: which parts of a mature version of a discipline ZOdyssey already practices are still missing here — and which parts are the same discipline under different words, not worth porting twice.

**Studied 2026-08-23** (verdict mapping, live re-reads, and inventories; this document written 2026-08-24). Sources of record, staged read-only under gitignored `.zcode/staging/` and never edited:

- `delegate-skills @ 2ecfa84d140cb34521471ce6cf5d358264865cbc` (17 implementer relays + the `delegate-setup` config author)
- `review-skills @ fe60a1a6c3d6cc7ddb2ed25b5f06f9e193181b25` (the `debate-review` and `babysit-pr` skills)

Provenance of the verdicts: one executor mapped every mechanism (run `study-delegate-review-skills`, todo 3), re-reading every DUPLICATE citation live; an independent `zodyssey:explore` pass re-read the same surface map first and its four drift reports were honored; the plan carrying these verdicts was co-reviewed by momus and `zodyssey:oracle`. Result: **42 mechanisms — 1 VIABLE, 33 DUPLICATE, 8 REJECTED.** The VIABLE produced candidate **C6** in [`docs/impl/00-INDEX.md`](impl/00-INDEX.md).

Citation grammar, and why it is strict: ZOdyssey-side claims are `path:line` and are content-pinned by `check-anchors` (a cited line that changes fails `npm test`). External claims appear ONLY as `repo@SHA <path> §<section>` — never the colon-line form on an external path. The reason is mechanical, not stylistic: a bare external cite whose basename collides with an in-tree file silently suffix-resolves to the in-tree file and pins the WRONG line (the resolver's dialect map, `scripts/check-anchors.mjs:123-141` — e.g. a bare `SKILL.md` cite resolves to `skills/odyssey/SKILL.md`). This was observed live during this study: a draft line citing a bare `SKILL.md` at line 10 made the checker fingerprint line 10 of the in-tree conductor prompt, not anything external (probe record in the run's todo-4 notepad). Out-of-tree targets cannot be pinned at all, so the SHA is the only freeze external claims have.

## Verdicts — delegate-skills (D-*)

### D-brief-contract — DUPLICATE
Mechanism (delegate-skills@2ecfa84d skills/claude-delegate/references/writing-the-brief.md §A compact structure, §One task per brief, §Premises freeze at dispatch): the brief is an explicit context contract for an implementer with NO orchestrator chat history — block-structured, one task per brief, premises frozen at dispatch, delivered via stdin never argv.
Covering capability: the plan's task grammar IS a brief contract — each todo block carries What to do / Must NOT do / Files / Wave / Blocked by / References / ALL-executable acceptance criteria / QA happy-failure scenarios (docs/DESIGN.md:188-204), and the 6-section dispatch prompt (TASK, EXPECTED OUTCOME, REQUIRED TOOLS, MUST DO, MUST NOT DO, CONTEXT with References paths) is the documented hand-off shape (skills/odyssey/SKILL.md:338-346). The executor is context-isolated by construction — "You have NO loyalty to the implementer and NO context beyond what is below" is the AUDITOR side of the same rule (skills/odyssey/references/auditor-prompt.md:12); the executor side is "ONE delegated todo" (agents/sisyphus-junior.md:17). Premises-freeze kin: the plan is sha-frozen at review (skills/odyssey/scripts/record-review.mjs:129-160) — the brief cannot change under the implementer mid-flight. The one deliberate divergence (pointers+delta instead of copy-everything-in) is ZOdyssey's stated context-economy rule (skills/odyssey/SKILL.md:348-352), a stronger form of the same contract.

### D-fleet-schema — REJECTED
Mechanism (delegate-skills@2ecfa84d skills/delegate-setup/references/schema.md §Implementer keys and dials): the `delegate-fleet.v1` config document — lanes of per-CLI autonomy dials (sandbox, permission mode, force) with validation and autonomy-contradiction checks.
Quoted principle (docs/DESIGN.md:51, §2): "**Our choice: hybrid, biased toward enforcement.**" A lane fleet with per-lane autonomy dials is a surface through which configuration WEAKENS enforcement — the autonomy-contradiction checks in the delegate schema exist precisely to police that surface. ZOdyssey has no user-configurable autonomy: the gates are hard-coded by design (the DESIGN §2 table, docs/DESIGN.md:53-60), and the one spawn that must write is pinned in code and stamped into the record (skills/odyssey/scripts/harness.mjs:73-81, `BASELINE_PERMISSION_MODE`, witnessed live). Adopting a fleet schema would create the config surface the enforcement bias exists to avoid.

Mechanism (delegate-skills@2ecfa84d skills/delegate-setup/scripts/implementers.mjs §IMPLEMENTERS): a frozen per-CLI capability table (binary, auth/model/usage probes, supported dials) as the single source of implementer truth.

### D-launch-hardening — DUPLICATE

### D-parity-gate — REJECTED
Mechanism (delegate-skills@2ecfa84d test/relay-parity.mjs §extract; delegate-skills@2ecfa84d CONTRIBUTING.md §Shared relay helpers): drift-proofing duplicated helpers without shared source — named symbols must stay byte-identical across all 17 relays, enforced by extraction and majority comparison.

A byte-parity gate enforces the invariant of a CONSTRAINT ZOdyssey does not have: delegate relays must stay single-file-installable, so helpers are copy-pasted 17 times and drift is the risk. ZOdyssey shares real modules — the exact drift hazard the parity gate polices was solved here by extraction, and the shared-verdict-schema comment witnesses the pattern: "Two of these lanes shared the SAME default object literal in TWO files … a drift hazard. This module is the single source of truth" (skills/odyssey/scripts/lib/verdict-schema.mjs:12-14). There is no duplicated-helper surface to gate.
